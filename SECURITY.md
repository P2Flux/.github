# Security policy

## Reporting a vulnerability

**Do not report security vulnerabilities through public GitHub issues, pull requests, or
discussions.** A public report is a disclosure: it reaches everyone, including whoever would use it,
before anything can be fixed.

A dedicated private disclosure channel will be published here before public launch. Until it is in
place, please use GitHub's private vulnerability reporting on the affected repository
(**Security → Report a vulnerability**), which is not visible to anyone but the maintainers.

We would rather hear about something that turns out to be nothing than not hear about it.

## Scope

These repositories: the contracts, the SDKs, and the documentation. The hosted API's source is
private; findings about the hosted service are in scope and should be reported the same way.

## What helps

- What you did, what happened, and what you expected instead
- Whether it is reproducible, and against which network and contract addresses
- Anything you already know about impact

Please do not run tests against other people's funds or against mainnet deployments. Base Sepolia is
free, and a testnet reproduction is worth exactly as much to us.

## What we will do

Acknowledge the report, tell you what we think it is, and keep you updated while it is being fixed.
If you would like credit when it is resolved, say so and we will ask before naming you.
